# LxBridge 交互与样式规范

本规范用于统一插件页面的操作流程、运行状态、错误诊断、风险确认和手机端信息层级。组件只负责展示，业务代码仍负责状态变化和接口调用。

## 1. 状态词与颜色

| 状态 | `data-tone` | 用途 |
| --- | --- | --- |
| 正常、完成 | `success` | 操作成功、服务可用 |
| 执行中 | `running` | 正在扫描、解析、下载 |
| 需关注 | `warning` | 部分失败、保护暂停、需要用户确认 |
| 失败 | `danger` | 操作无法继续 |
| 未开始、未启用 | `neutral` | 尚无结果或可选功能关闭 |

状态不能只依赖颜色，必须同时显示文字。

## 2. 步骤卡片

- 容器：`.ui-step-list`
- 单步：`.ui-step-card`
- 编号：`data-step="1"`
- 状态：`data-state="pending|active|complete|disabled"`
- 一个页面同时只突出一个 `active` 步骤。
- 步骤标题描述用户目标，不使用内部接口名。

通过 `LxUI.stepCard()` 生成基础结构。

## 3. 状态卡片

- 容器：`.ui-status-grid`
- 单卡：`.ui-status-card`
- 状态：`data-tone="success|running|warning|danger|neutral"`
- 固定顺序：状态点、类别、主要结论、短标签、摘要、可选诊断。
- 摘要控制在两行内，原始错误放入折叠诊断。

通过 `LxUI.statusCard()` 生成基础结构。运行诊断的下载队列和音源保护已作为首个接入示例。

## 4. 摘要与折叠诊断

- 使用 `.ui-diagnostic` 或 `LxUI.diagnostic()`。
- 默认展示用户能理解的结论和建议。
- 折叠区才显示请求地址、文件路径、退出码和原始错误。
- 提供复制功能时，复制内容可以包含原始诊断，但不得包含密码或令牌。

## 5. 高风险操作

- 执行前必须展示确认窗口。
- 使用 `.ui-impact-preview` 或 `LxUI.impactPreview()` 展示影响数量、目标范围、不可恢复内容和明确保留的内容。
- 主按钮使用具体动词，例如“取消 12 个任务”，不能只写“确定”。
- 破坏性主按钮使用危险色；取消按钮始终可见。

## 6. 手机端信息层级

- 第一层：歌名、状态、主要按钮。
- 第二层：歌手、音质、进度等必要摘要。
- 第三层：格式、容量、完整路径、来源和原始错误，放入 `.ui-mobile-details`。
- 次要内容使用 `.ui-mobile-secondary`，只在详情展开后显示。
- 操作区使用 `.ui-action-row`，手机端自动变为单列全宽按钮。

## 7. 设置搜索

设置卡片后续统一添加：

- `data-settings-title`：设置名称。
- `data-settings-keywords`：同义词和功能关键词。
- `data-settings-category`：所属分类。

搜索只影响显示，不修改任何设置；无结果时必须提供清除搜索入口。

## 8. 文案规则

- 先说结果，再说原因，最后给建议。
- 避免把技术异常直接作为主标题。
- “完成”必须表示业务结果已完成，不能只表示请求已发送。
- “文件已存在”必须经过实际文件检查，不能只依据曲库记录。
- 数量、目录、目标音质和不可恢复影响必须在确认前展示。
